# Использование сайта и API

1. Открыть адрес работающего сайта. Ввести выданный командой ключ и нажать «Подключиться». Сообщение о загруженной модели проверяет health; действительность ключа устанавливает защищённый запрос.
2. Выбрать MOV и нажать «Проверить видео». На странице действует текущая политика: до128MiB,180секунд; остальные пределы — в раскрытии «Технические ограничения». Эти ограничения выбрала команда, кейс их не задаёт как универсальные пределы тестов.
3. Дождаться результата. Страница показывает состояние задания без выдуманных процентов и ETA. Не закрывать страницу: ключ и текущий job хранятся только в её памяти.
4. При событиях проверить каждый тип, время и полное описание. Открыть кадр для увеличения; исходные пропорции сохраняются. Закрыть Escape. Кандидат нормативного основания не является подтверждённым правовым выводом.
5. Техническая ошибка означает, что результат не установлен. «Нарушение не обнаружено» допустимо только для завершённого анализа, но не гарантирует отсутствие всех нарушений.
6. При смене ключа в существующем задании переподключиться: сайт восстанавливает получение по job_id, не загружая видео повторно. После неопределённого исхода POST не нажимать повтор вслепую: возможно создание дубликата.
7. «Проверить другое видео» начинает новый просмотр. «Очистить ключ и данные страницы» удаляет данные из памяти страницы; это не команда удаления результата на сервере.

## API жюри

POST `/api/v1/analyze`: `multipart/form-data`, ровно поле `file`, MOV; ключ в `X-API-Key`. Ответ с `job_id` означает приём, а не успешный анализ. Далее GET `/api/v1/jobs/{job_id}` с тем же ключом, ориентир опроса2секунды.

`processing` — работа продолжается; `done` — `verdict` и `violations`; `failed` — техническая ошибка, verdict отсутствует. Для каждого события: `type`, `timecode_sec`, `description`, `evidence_frames` с1–3JPEG/base64 и `timestamp_sec`. Времена — секунды от начала исходного видео. Не включать префикс data URL в `image_base64`.

Веб-сайт поддерживает существующий ответ приёма200 и допустимый202. По кейсу важны пути, ключ, job_id и формат результата; сам код202 не предписан. После сетевой ошибки POST автоматического повтора нет.

Приватные тестовые видео, кадры и описания нельзя публиковать, передавать сторонним AI API или использовать для обучения. Все вычисления модели должны выполняться внутри собственного развёрнутого сервиса команды.
