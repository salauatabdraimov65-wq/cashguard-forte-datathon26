# CashGuard — выявление нарушений кассовой дисциплины по видео (ForteBank Datathon 26)

AI-сервис принимает видео `.mov` с камеры кассы и возвращает вердикт (`violation` / `no_violation`),
для каждого нарушения — тип, таймкод, описание с пунктом норматива РК и 1–3 кадра-доказательства.
Всё работает локально на GPU-поде (NVIDIA L4), без сторонних AI API.

## Архитектура

```
сайт / API жюри → FastAPI (serve_site.py: сайт + API, X-API-Key, очередь)
               → базовый пайплайн команды: YOLO11m (люди+трекинг), YOLO11m-pose, дообученный детектор денег/сумок/сейфа,
                 Qwen3.5-9B (вопросы да/нет по кадрам), правила событий
               → надстройка addon.py «конечное состояние»: стол пуст? деньги/сумка/планшет? ноутбук активен? дверь? сейф/ящик?
                 + поиск момента начала → таймкод
               → каталог нормативов (тип → пункт) → JSON по схеме жюри
```

Модели не обучаются «под ответы» на 40 видео: предобученные модели отвечают на узкие вопросы, решение принимают правила.
Пункт норматива берётся из фиксированного каталога, модель его не генерирует.

## Структура

| Путь | Что |
|---|---|
| `service/serve_plus.py` | API по схеме жюри (`POST /api/v1/analyze`, `GET /api/v1/jobs/{job_id}`, `/health`) |
| `service/addon.py` | надстройка: проверка конечного состояния (блок `audit`), каталог нормативов |
| `service/serve_site.py` | сайт + API на одном адресе |
| `site/` | собранный фронтенд и `forte_site.py` |
| `notebooks/03v2_detector_honest.ipynb` | дообучение детектора с разбиением по видео (без утечки) + честные таймлайны |
| `tools/augment.py` | синтетические копии видео (зеркало, перспектива, свет) для проверки устойчивости |
| `tools/api_eval.py` | прогон видео через API, как это делает жюри |
| `app/src/` | базовый пайплайн команды (`src.pipeline.Analyzer`) |
| `docs-backend/` | документы фронтенда/интеграции |

## Запуск на поде

```bash
python -m pip install -q fastapi uvicorn python-multipart
cd /workspace && YOLO_OFFLINE=1 WORK=/workspace CASHGUARD_API_KEY="$(cat /workspace/api_key.txt)" \
  nohup python -m uvicorn serve_site:app --app-dir /workspace/forte-release --host 0.0.0.0 --port 8000 --workers 1 \
  > /workspace/serve_site.log 2>&1 &
```

Ожидаемое размещение: `serve_plus.py`, `addon.py`, `app/src/` и веса в `/workspace`; `serve_site.py`, `forte_site.py`, `site-dist/`
в `/workspace/forte-release`. Ключ API хранится только в `/workspace/api_key.txt` и в репозиторий не попадает.

## Результаты (открытая выборка, 40 уникальных видео, 21 с нарушением)

| Конфигурация | Набор | Верный вердикт | Найдено | Ложные |
|---|---|---|---|---|
| база + надстройка (в сервисе) | исходные | 34/40 (85%) | 17/21 | 2/19 |
| базовый пайплайн | исходные | 31/40 (77.5%) | 13/21 | 1/19 |
| база + надстройка | зеркальные копии | 30/38 (79%) | 18/20 | 6/18 |
| базовый пайплайн | зеркальные копии | 24/38 (63%) | 11/20 | 5/18 |

Время: медиана 17 с, максимум 58 с на видео (лимит 300 с). Метрики получены на открытой выборке и скорее завышены.

## Ограничения

Не распознаются нарушения «по бездействию» (недовыдача, нет проверки удостоверения); ключ в сейфе слишком мелок для 464 px;
известное ложное срабатывание при выключенном свете; таймкод надстройки — момент, когда состояние установилось.
YOLO11 распространяется под AGPL-3.0 — для коммерческого внедрения нужна лицензия или замена (например, RT-DETR, Apache-2.0).
Результат — подсказка для проверяющего, а не юридическое заключение. Видео, кадры и разметка хакатона в репозиторий не включены.
